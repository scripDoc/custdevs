# trim_video

## Идеология

Для кастдева видео не нужно — нужен только звук для transcribe.py. Поэтому **дефолт скилла — audio-only**, выход всегда `.m4a` в `clients/<slug>/01_audio/`. Это:
- решает все проблемы совместимости контейнеров (webm/vp8 → mp4 уже не дёрнется)
- даёт `transcribe.py` оптимальный вход
- экономит место и время

Видео сохраняется только если пользователь явно сказал «нужно с видео».

- «вырежи кусок с <время> по <время> из <файла>»

## Что делает

1. Парсит из фразы: имя файла (или часть имени), таймкод начала, таймкод конца, режим (audio по дефолту, video если явно).
2. Понимает форматы времени:
   - `1:30`, `01:30` → MM:SS
   - `1:30:00`, `00:01:30` → HH:MM:SS
   - `90 секунд` → секунды
   - `1 минута 30`, `1 мин 30 сек` → MM:SS
3. Ищет файл (если не дали полный путь). Приоритет:
   1. `clients/<current>/00_raw/` — основное место для исходников клиента
   2. `inbox/` — транзитный буфер пользователя (см. шаг 8: после обрезки файл будет скопирован в 00_raw и удалён из inbox)
   3. `~/Загрузки/`, `~/Downloads/`, `~/Desktop/`, `~/Видео/`, `~/Videos/`, `~/Документы/`
   4. Если найдено несколько подходящих — самый свежий по mtime
4. Если клиентская папка не определена — спрашивает одним вопросом: «В папку какого клиента положить?»
5. Проверяет длительность входа через `ffprobe`, валидирует границы.
6. **Audio-режим (дефолт):** извлекает только звук в `.m4a` (AAC). Это всегда работает, не зависит от исходного контейнера/кодека.
7. **Video-режим (по явному запросу):** выбирает стратегию по таблице совместимости (см. раздел ниже) — `-c copy` если кодеки укладываются в целевой контейнер, иначе перекодирование.
8. **Архивирование исходника:**
   - Если исходник был внутри `clients/<slug>/00_raw/` — оставить на месте (он уже архивирован).
   - Если исходник был в `inbox/` — после успешной обрезки **скопировать** в `clients/<slug>/00_raw/` и **сразу удалить** из inbox (`cp <src> <dst> && rm <src>`). Если cp упал — НЕ удалять из inbox. Сообщить пользователю: «Скопировал `<filename>` в `clients/<slug>/00_raw/`, убрал из inbox. Бэкап у тебя на устройствах.»
   - Если исходник был снаружи (`~/Загрузки/` и т. п.) — после успешной обрезки **переместить** его в `clients/<slug>/00_raw/`. Если файл с таким именем там уже есть — добавить суффикс `_2`, `_3` и т. д. к новому, не перезаписывать.
   - Сообщить пользователю одной строкой: «Исходник перемещён в `clients/<slug>/00_raw/<filename>` — там он останется как архив».
   - **Никогда** не удалять исходник из `00_raw/` после обрезки — он нужен для повторных прогонов с другими таймкодами или другой моделью Whisper.
   - **Никогда** не трогать другие файлы в `inbox/` — только тот, который сам взял для текущей обрезки.
9. Запоминает результат как «свежий аудио файл клиента» — следующий вызов transcribe возьмёт его автоматически.
10. Отчитывается одной-двумя строками.

## Параметры из контекста

| Параметр | Источник | Пример |
|---|---|---|
| `input` | имя/часть имени из фразы или последний скачанный файл (поиск: `00_raw/` → `inbox/` → `~/Загрузки/` → ...) | `inbox/alex_klub_recording.m4a` |
| `start` | таймкод начала | `00:01:30` |
| `end` | таймкод конца | `00:45:00` |
| `client_slug` | текущий клиент сессии | `vladimir` |
| `mode` | `audio` (дефолт) или `video` (по явной фразе) | `audio` |
| `output` | `clients/<slug>/01_audio/<name>.m4a` (audio) или `<name>_trimmed.<ext>` (video) | `clients/vladimir/01_audio/Telemost_2026-05-01.m4a` |

## Команды

### Audio-режим (дефолт)

```bash
ffmpeg -y -ss <start> -to <end> -i <input> \
    -vn -c:a aac -b:a 192k \
    <client_dir>/01_audio/<name>.m4a
```

`-vn` отключает видео-поток. AAC 192 kbps — overkill по качеству, но для речи запас не вредит, и transcribe.py одинаково хорошо ест что бы там ни было. `.m4a` — стандартный AAC-контейнер, faster-whisper его читает напрямую.

### Video-режим, copy (быстро, без перекодирования)

```bash
ffmpeg -y -ss <start> -to <end> -i <input> -c copy <output>
```

Использовать только если кодеки совместимы с целевым контейнером (см. таблицу).

### Video-режим, re-encode (медленнее, но универсально)

```bash
ffmpeg -y -ss <start> -to <end> -i <input> \
    -c:v libx264 -preset fast -crf 23 \
    -c:a aac -b:a 192k \
    <output>
```

Использовать когда `-c copy` не работает: webm→mp4, vp8/vp9→mp4, opus→mp4 (без отдельной обработки), артефакты на границе.

## Живой прогресс ffmpeg

Обрезка длинных записей (часовые кастдевы) идёт 1–5 минут. Без живого прогресса пользователь не понимает — процесс идёт или завис. Поэтому ffmpeg **всегда** запускается в фоне с парсингом stderr. Это применимо при любом вызове скилла — отдельно или в составе `kickoff`.

**Логика:**

1. Запустить ffmpeg-команду в `run_in_background: true`.
2. Каждые **15–30 секунд** опрашивать `BashOutput`/`TaskOutput` по shell_id.
3. В stderr ffmpeg печатает строки вида:
   ```
   frame=12345 fps=50.0 q=-1.0 size=10240kB time=00:25:30.12 bitrate=178.4kbits/s speed=28x
   ```
4. Парсить из последней такой строки `time=HH:MM:SS.ss`.
5. Считать процент относительно длительности обрезки `(end_seconds - start_seconds)` (или полной длительности входа если `end` не задан).
6. Перезаписывать строку статуса (не добавлять новую каждый тик).

**Формат вывода (live):**

```
⏳ Обрезка <start>–<end>
        └─ ffmpeg: 47% (35:12 из 74:22, speed 28x)
```

**Формат вывода (финал):**

```
✅ Обрезка <start>–<end>    clients/<slug>/01_audio/<slug>.m4a (74:22, 100 МБ, 4с)
```

**Регламент частоты обновлений:**

- Не чаще **раза в 15–20 с** — иначе спам токенами.
- Не реже **раза в 60 с** — иначе пользователь думает, что висит.
- Финальное обновление обязательно — с итоговыми цифрами (длительность работы, размер выхода).

В audio-режиме ffmpeg обычно работает на скорости x20–x40 (CPU-AAC encoding не нагружает машину), поэтому 74-минутная обрезка занимает ~3–4 секунды. Иногда хватает одного финального тика без промежуточных, но фоновый запуск всё равно обязателен — это страховка от случаев, когда исходник на медленном диске или большой контейнер с множеством стримов.

## Распознавание формата входа

Перед video-режимом проверить кодеки через `ffprobe`:

```bash
ffprobe -v error -select_streams v:0 -show_entries stream=codec_name -of default=noprint_wrappers=1:nokey=1 <input>
ffprobe -v error -select_streams a:0 -show_entries stream=codec_name -of default=noprint_wrappers=1:nokey=1 <input>
```

Таблица решения (целевой контейнер — `.mp4`, если пользователь не сказал иначе):

| Вход | Видео-кодек | Аудио-кодек | Стратегия |
|---|---|---|---|
| `.mp4` | h264 | aac | `-c copy` |
| `.mp4` | h265/hevc | aac | `-c copy` |
| `.mov` | h264 | aac | `-c copy` (mp4 совместим) |
| `.webm` | vp8 / vp9 | opus | **re-encode** (vp8/vp9 не лезут в mp4) |
| `.mkv` | любой | любой | re-encode (или сменить контейнер на `.mkv` через `-c copy`) |
| прочее / неясно | — | — | re-encode |

Если пользователь явно указал нестандартный целевой контейнер (например, «сохрани в webm») — копировать или перекодировать по той же логике относительно его контейнера.

В audio-режиме эта таблица не нужна — `-vn -c:a aac` всегда работает независимо от исходных кодеков.

## Архивирование исходника — детали

После успешной обрезки и только если исходник был снаружи `clients/<slug>/00_raw/`:

```bash
# Конфликт имён в 00_raw — добавить суффикс (общая логика для всех источников)
target="clients/<slug>/00_raw/<filename>"
if [ -e "$target" ]; then
    base="${filename%.*}"
    ext="${filename##*.}"
    n=2
    while [ -e "clients/<slug>/00_raw/${base}_${n}.${ext}" ]; do
        n=$((n + 1))
    done
    target="clients/<slug>/00_raw/${base}_${n}.${ext}"
fi

# Если из inbox/ — копирование + удаление при успехе
cp "inbox/<filename>" "$target" && rm "inbox/<filename>"
# (если cp упал — rm не выполнится, файл в inbox остался для повтора)

# Если из ~/Загрузки/ или другого внешнего места — перемещение
mv "<original_path>" "$target"
```

**inbox** — транзитный буфер: копируем + удаляем сразу после успеха копирования. Оригиналы у пользователя на устройствах (телефон, диктофон).

**`~/Загрузки/`** и т. п. — перемещение, не копирование: эта папка чистится сама собой по мере того как пользователь обрабатывает кастдевы. Если перемещение упало (cross-device, нет прав) — сделать `cp + rm`, если и это не получилось — оставить исходник на месте и сообщить пользователю.

## Обработка ошибок

- **Файл не найден:** перечислить что нашёл в типовых папках, спросить уточнения.
- **end ≤ start:** сообщить, не запускать.
- **end больше длительности файла:** усечь end до длительности, предупредить.
- **ffmpeg вернул код ≠ 0 в audio-режиме:** показать последние 10 строк stderr. Если в сообщении `Could not find tag for codec` — это про несовместимость кодека с контейнером, в audio-режиме это исключено (мы всегда aac в m4a), значит проблема в чём-то другом — не догадываться, отдать пользователю.
- **ffmpeg вернул код ≠ 0 в video-режиме на `-c copy`:** автоматически попробовать re-encode и предупредить, что займёт дольше.
- **`-c copy` дал кривые границы (длительность отличается от ожидаемой больше чем на 1 с):** перейти на re-encode.
- **Двух неудач хватит:** не пытаться третий раз, отдать пользователю что получилось и спросить.
