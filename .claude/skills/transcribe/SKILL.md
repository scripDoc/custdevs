# transcribe

## Перед выполнением

Прочитай `failures.md` (grep по тегам этого скилла) — если есть релевантные записи, учти их в плане. Не объясняй пользователю что делаешь grep — это фоновая проверка.

**Теги для этого скилла:** #transcribe, #deepgram, #diarization, #api, #network, #env, #whisper (исторические записи про faster-whisper оставлены в логе как контекст)

## Триггеры

- «транскрибируй <клиент>» / «расшифруй запись <клиент>»
- «запусти расшифровку для <клиент>»
- «обработай аудио <клиент>»
- «транскрибируй <конкретный файл>»

## Что делает

Транскрибация идёт через **Deepgram Nova-3 (облако) + диаризация v2** — разделение спикеров «кто говорит» из коробки. Локальные ресурсы (GPU, voice-input daemon) не трогаются.

1. Определяет клиента — из фразы или из контекста разговора (слот «текущий клиент сессии» от new_client / trim_video).
2. Находит свежий аудио/видео файл в `clients/<slug>/01_audio/`:
   - **Приоритет №1: файлы с суффиксом `*_enhanced.*`** (после `enhance_audio`). Если такой файл есть — используется он, оригинал игнорируется. Чистое аудио = лучше транскрипция и точнее диаризация.
   - Приоритет №2: файлы с суффиксом `*_trimmed.*` (после trim_video в видео-режиме).
   - Если в папке только один файл (без суффиксов) — он.
   - Если несколько подходящих в одной приоритетной группе — самый свежий по mtime.
3. Запускает `transcribe.py` — он сам читает ключ `DEEPGRAM_API_KEY` из `custdevs/.env` (или из окружения), отправляет файл в Deepgram, получает транскрипт с таймкодами и спикерами.
4. По ходу прокидывает stdout пользователю — скрипт печатает прогресс (загрузка → обработка → готово).
5. После завершения — отчёт: длительность аудио, время обработки, скорость (xN), число спикеров, путь к `.transcript.md`, **первые 300 символов** расшифровки чтобы убедиться что не каша.
6. Подсказывает следующий шаг: «Готов запустить структурный разбор по `templates/structure_prompt.md` — скажи "разбери" или "сделай структуру".»

## Параметры из контекста

| Параметр | Источник | Пример |
|---|---|---|
| `client_slug` | имя из фразы / текущий клиент сессии | `vladimir` |
| `input` | свежий файл из `01_audio/` (приоритет `_enhanced` → `_trimmed` → остальное) или явный путь из фразы | `clients/aleksandr/01_audio/aleksandr_enhanced.m4a` |
| `output_dir` | всегда `clients/<slug>/02_transcript/` | — |

## Команды

```bash
# Найти свежий файл
ls -t clients/<slug>/01_audio/

# Транскрибация через Deepgram (диаризация включена по умолчанию)
python3 -u scripts/transcribe.py <input> -o clients/<slug>/02_transcript/

# Если диаризация не нужна (монолог, один спикер):
python3 -u scripts/transcribe.py <input> -o clients/<slug>/02_transcript/ --no-diarize

# Язык можно зафиксировать явно (по умолчанию multi = multilingual):
python3 -u scripts/transcribe.py <input> -o clients/<slug>/02_transcript/ --language ru
```

Дефолты скрипта: `model=nova-3`, `language=multi`, `diarize-version=v2`, `timeout=600`. Diarize v2 авто-детектит число спикеров — задавать min/max не нужно (API их не принимает).

## Формат вывода

Три файла в `clients/<slug>/02_transcript/`:
- `<name>.transcript.md` — markdown, **обратно совместим** со старым форматом: те же таймкоды `**[ЧЧ:ММ:СС–ЧЧ:ММ:СС]**`, добавлена метка спикера `[Спикер N]`:
  ```markdown
  **[00:00:12–00:00:18]** [Спикер 0] Расскажи чем занимаешься, как устроено?

  **[00:00:18–00:00:45]** [Спикер 1] Ну смотри, у меня автосервис, делаем оптику...
  ```
- `<name>.transcript.txt` — плоский текст без разметки.
- `<name>.transcript.json` — нормализованные сегменты + полный сырой ответ Deepgram (для отладки).

Спикеры — `Спикер 0`, `Спикер 1`, … из диаризации (целые индексы Deepgram). Кто из них интервьюер, а кто клиент — определяется по содержанию при разборе; при желании пользователь может пометить руками.

## Обработка ошибок

- **Папка `clients/<slug>/01_audio/` пустая:** сказать пользователю, что аудио ещё не положено.
- **Файла из фразы нет:** перечислить что есть в `01_audio/`.
- **`DEEPGRAM_API_KEY не задан`:** ключа нет в `custdevs/.env`. Попросить пользователя заполнить `.env` (шаблон — `.env.example`). Не продолжать.
- **Сетевая ошибка / таймаут Deepgram:** показать сообщение, предложить повтор (это транзиентная проблема). При повторном падении — стоп, не долбить третий раз.
- **Транскрипция дала кашу** (не та речь / пустой результат / странные символы): предупредить пользователя — возможно проблема записи или неверный язык (попробовать `--language ru` вместо `multi`).

## Живой прогресс

Deepgram pre-recorded — это один HTTP-запрос: файл целиком загружается и обрабатывается на стороне облака, ответ приходит разом. Прогресс в процентах недоступен, но обработка быстрая (час аудио — обычно 0.5–2 минуты).

**Логика:**

1. Запустить `python3 -u scripts/transcribe.py ...` (флаг `-u` — чтобы stdout не буферизовался). Для длинных файлов — в `run_in_background: true`, иначе можно синхронно.
2. Скрипт сам печатает стадии и heartbeat каждые 10с, пока идёт запрос:
   ```
   📂 Файл: ... (12.3 МБ)
   ☁️  Провайдер: Deepgram (nova-3, язык=multi, диаризация=v2)
   ⬆️  Загрузка и обработка (timeout 600с)...
     ⏳ Deepgram обрабатывает... 10с
     ⏳ Deepgram обрабатывает... 20с
   ✅ Готово за 34с (01:14:22 аудио, x131.2 к реальному времени)
      Спикеров: 2, сегментов: 412
   ```
3. Если шёл в фоне — опрашивать `BashOutput`/`TaskOutput` каждые 15–20с, показывать пользователю последнюю строку статуса.
4. Финальное обновление обязательно — со средней скоростью, числом спикеров и путём к `.transcript.md`.

## После выполнения

Оценить результат по трём критериям:

1. **Провал/исправление** — что-то ломалось (сеть, ключ, формат ответа) → запись в `failures.md` с тегами `#deepgram #network` / `#deepgram #env`.
2. **Деградация** — отклонение от ожидаемого (плохая диаризация — все реплики на одного спикера; мусорный текст; неожиданно медленный ответ) → запись с тегом `#performance` или `#quality #diarization`.
3. **Неочевидное знание** — обнаружилась особенность Deepgram/окружения → запись с тегом `#environment`.

Если ничего из трёх — ничего не пиши.

В отчёте пользователю упоминай факт записи кратко: «Записал в failures.md (теги: #X #Y)».
