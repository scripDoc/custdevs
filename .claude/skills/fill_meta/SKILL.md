# fill_meta

## Перед выполнением

Прочитай `failures.md` (grep по тегам этого скилла) — если есть релевантные записи, учти их в плане. Не объясняй пользователю что делаешь grep — это фоновая проверка.

**Теги для этого скилла:** #meta, #fill_meta, #autofill, #prompt, #transcript

## Идеология

Ручное заполнение meta.md — это работа, которую можно сделать на 80% автоматически. Из расшифровки видно: чем человек занимается, что у него за рутины, что пробовал из AI, какие фразы у него «золотые» и просятся обратно на закрытии. Всё это скилл вытащит сам. Останется только то, что в текст не попадает: невербалика, темп речи, внутренние реакции автора — это пользователь докинет руками за 5–10 минут.

## Триггеры

- «заполни мету для <клиент>»
- «собери meta для <клиент>»
- «обнови meta из расшифровки»
- «автозаполнение мета»
- «заполни меты <клиент>»

## Что делает

1. Определяет клиента — из фразы или из контекста разговора («текущий клиент сессии»).
2. Проверяет наличие свежей расшифровки в `clients/<slug>/02_transcript/*.transcript.md`. Если несколько — берёт самую свежую по mtime. Если ни одной — сообщает, что сначала надо транскрибировать.
3. Читает текущий `clients/<slug>/meta.md` — нужно для двух вещей: видеть что уже заполнено руками (не перезаписывать), и сохранить как `meta.md.backup` перед перезаписью.
4. Делает бэкап: `cp clients/<slug>/meta.md clients/<slug>/meta.md.backup`. Если бэкап уже существует — добавляет суффикс с датой/временем (`meta.md.backup.2026-05-01_03-45`), не перезаписывает старые бэкапы.
5. Применяет промпт из `templates/meta_prompt.md`:
   - Читает шаблон промпта целиком
   - Подставляет вместо `<содержимое clients/<slug>/meta.md>` — реальное текущее содержимое
   - Подставляет вместо `<содержимое .transcript.md>` — содержимое свежей расшифровки
   - Прогоняет получившийся промпт через себя (Claude в текущем чате — не отдельный API-вызов), генерирует заполненный markdown
6. Записывает результат в `clients/<slug>/meta.md` (поверх старого, бэкап уже сделан).
7. Показывает пользователю краткий diff: какие разделы заполнены автоматически, какие остались с пометкой `[заполнить руками]`, какие наблюдения попали в финальный блок `## Что я (Claude) заметил при разборе`.
8. Запоминает что meta для клиента готова — следующий шаг workflow это `structure_prompt`.

## Параметры из контекста

| Параметр | Источник | Пример |
|---|---|---|
| `client_slug` | имя из фразы / текущий клиент сессии | `vladimir` |
| `transcript_path` | свежий `*.transcript.md` в `02_transcript/` | `clients/vladimir/02_transcript/telemost_30-04-26.transcript.md` |
| `meta_path` | всегда `clients/<slug>/meta.md` | — |
| `backup_path` | `meta.md.backup` или с суффиксом времени, если уже есть | — |
| `prompt_template` | всегда `templates/meta_prompt.md` | — |

## Команды

```bash
# Бэкап (с защитой от затирания старых бэкапов)
cp clients/<slug>/meta.md clients/<slug>/meta.md.backup
# или, если уже есть:
cp clients/<slug>/meta.md "clients/<slug>/meta.md.backup.$(date +%Y-%m-%d_%H-%M)"

# Чтение трёх входов через Read tool — не через cat
# (промпт-шаблон, текущий meta, свежая расшифровка)

# Запись результата через Write tool — поверх meta.md
```

В этом скилле bash минимален: только бэкап. Основная работа — чтение/подстановка/запись через инструменты Read и Write.

## Обработка ошибок

- **Расшифровки нет в `02_transcript/`:** сказать пользователю, что сначала надо транскрибировать.
- **`meta.md` отсутствует** (клиент не создан полностью): спросить — создать новый или работаем с существующей папкой.
- **`templates/meta_prompt.md` не найден:** сообщить пользователю, не пытаться угадать промпт.
- **Несколько расшифровок:** взять самую свежую, упомянуть в отчёте какую именно. Если пользователь явно назвал файл — взять его.
- **Если на промпте Claude вернул что-то невалидное** (не markdown, не структура шаблона): не записывать, показать пользователю что получил и спросить.

## Отчёт пользователю

Структура:

```
✅ Заполнил meta.md для <Имя> на основе <transcript>.
   Бэкап: clients/<slug>/meta.md.backup[.timestamp]

Заполнено автоматически:
  • Кто этот человек
  • Что узнал про дело
  • Что съедает время (с таймкодами цитат)
  • Куда хочет прийти
  • Что пробовал из AI
  • Точные цитаты — N штук

Оставлено под ручное заполнение:
  • Особенности характера и общения
  • Невербалика и интонации
  • Контекст до созвона
  • Внутренние реакции автора

Мои наблюдения попали в раздел `## Что я (Claude) заметил при разборе`.

Дальше: дополни meta руками (~5–10 мин), потом скажи «разбери» — запущу структурный разбор.
```

## После выполнения

Оценить результат по трём критериям:

1. **Провал/исправление** — что-то ломалось → запись в `failures.md`.
2. **Деградация** — отклонение от ожидаемого (скорость, качество, неожиданный fallback) → запись с тегом `#performance` или `#quality`.
3. **Неочевидное знание** — обнаружилась особенность окружения → запись с тегом `#environment`.

Если ничего из трёх — ничего не пиши.

В отчёте пользователю упоминай факт записи кратко: «Записал в failures.md (теги: #X #Y)».
