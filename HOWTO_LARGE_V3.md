# HOWTO — прогнать кастдев через large-v3

## Зачем

Дефолт системы — `medium`. На GTX 1650 SUPER (4 GB VRAM) постоянно крутится
voice-input daemon, он держит ~2 GB. На `large-v3` свободной памяти не хватает —
падает по `out of memory` даже в `int8_float16`.

Для критичных случаев large-v3 даёт +2–4 п.п. WER на русском, лучше тянет
англицизмы и шум. Чтобы её использовать — временно останови voice-input.

## Когда GPU свободна, когда занята

`transcribe.py` теперь сам определяет это по факту:
- Если cuda работает → идёт через GPU (быстро)
- Если cuBLAS не справился → автоматически переключается на CPU и предупреждает (медленнее, но стабильно)

Чтобы гарантированно был GPU — `systemctl --user stop voice-input` перед запуском.

## Когда переключаться на large-v3

- Плохое качество записи (помехи, далеко от микрофона, шумный фон)
- Много англицизмов / технической терминологии / редких имён
- Важный клиент, где важна каждая формулировка для возврата ему его же слов

## Когда НЕ переключаться

- Обычный кастдев на чистом русском в тихой комнате
- Разница medium vs large-v3 на структурном разборе (`03_structure.md`) почти
  незаметна — Claude всё равно вытащит смысл из medium-расшифровки

Не переплачивай временем без причины: medium на этой GPU считает в ~3–5x быстрее.

## Команды

```bash
# 1. Остановить voice-input
systemctl --user stop voice-input

# 2. Убедиться что VRAM освободилась (~3.5 GB должно быть доступно)
nvidia-smi | head -10

# 3. Прогнать large-v3
python3 custdevs/scripts/transcribe.py \
    custdevs/clients/<имя>/01_audio/call.m4a \
    -o custdevs/clients/<имя>/02_transcript/ \
    --model large-v3

# 4. Вернуть voice-input на место
systemctl --user start voice-input
```

## Если всё равно падает по VRAM

Даже без voice-input large-v3 в `float16` влазит впритык. Если упало:

```bash
python3 custdevs/scripts/transcribe.py call.m4a -o /tmp/ \
    --model large-v3 --compute-type int8_float16
```

`int8_float16` экономит ~30% памяти, потеря качества пренебрежимая.

В `transcribe.py` уже есть автоматический fallback: если `float16` падает по OOM —
скрипт сам переключается на `int8_float16`. Так что в большинстве случаев ничего
указывать не надо.

## На другой машине

Этот файл и связанные ограничения — машинно-зависимые. Если пересядешь на
железо с большей VRAM (8 GB+), просто верни в `transcribe.py` дефолт
`large-v3` и удали этот HOWTO.
