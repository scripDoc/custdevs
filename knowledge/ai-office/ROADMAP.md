# AI-Office ROADMAP

Живой план реализации мульти-агентной системы для производства лендингов под клиентов кастдева. Источник истины по архитектуре офиса.

## Архитектура

### Pipeline (sequential, файловый handoff)
транскрипт кастдева (с диаризацией)
→ client-strategist     [что клиент хочет — по реакции, взвешенно]
→ product-architect     [фильтр реализуемости + реальные цифры, 2 выхода]
→ dr-copywriter         [продаёт хотелки в рамках реального]
→ landing-designer      [дизайн из копи]
→ frontend-dev          [код + деплой]
Директор — оркеструет всю цепочку, ведёт диагностику. Обязателен для боевой работы.

### Два этапа внедрения
- ЭТАП 1 (сейчас): прямой прогон. Линейный pipeline, агенты пишут заметки в _agent_notes.md, человек читает вручную. Без интерактива.
- ЭТАП 2 (после рабочей первой версии): "поднятие руки" + эскалация через Директора. Агент задаёт вопрос/предложение/предупреждение → Директор маршрутизирует к нужному агенту (напр. копирайтер → уточнить у стратега через Директора). Предложения архитектора стратегу обсуждаются здесь.

### Принципы
- Каждый агент ДОВЕРЯЕТ предыдущему и углубляет, НЕ перепроверяет с нуля. Не дублировать роли → видно какой этап проседает.
- Источник истины — транскрипт с диаризацией. Производные файлы (старые meta/structure/package по PDF-логике) НЕ давать агентам — искажают. Только стратег читает транскрипт, остальные доверяют артефакту предыдущего.
- Узнавание, не пересказ: клиент должен УЗНАВАТЬ свою картину ("да, вот это я искал"), а не слышать пересказ слов. Не цитировать в лоб.
- Баланс: резонировать с миром клиента + держать планку качества презентации. Не гладкий корпоративный маркетинг, но и не сырые цитаты.
- Взвешивание реакции клиента (стратег): три уровня (высокий/средний/низкий), не бинарно. При сомнении — перечитать транскрипт глубже. Калибровать по личности клиента.
- Честность + эскалация: не знаешь → ищи в интернете (где разрешено) → не решил → Директор → не решил → Алик. Не замалчивать, не придумывать.
- Модель-тиринг: Директор=opus, дизайнер=opus, остальные=sonnet (по ситуации).

## Агенты

### client-strategist ✅ собран, отлажен
Вход: транскрипт. Выход: strategist_brief.md.
Анализирует что клиент хочет по реакции (взвешивание), различает спикеров, формирует разделы: аватар / awareness (Schwartz) / оффер / механизм / VoC-цитаты / "Стоп-лист: не использовать" / "Слабые сигналы на будущее".
Tools: Read, Write, Glob, Grep, Skill.

### product-architect — фильтр реализуемости (КРИТИЧНОЕ звено) 🛠 собран (черновик, не тестирован)
Проблема которую решает: pipeline продаёт желания, не проверяя реализуемо ли. Сочинённые цифры ("за 5 минут" — откуда?) недопустимы.
Роль: ДАЁТ копирайтеру что нужно (реальное + цифры + возможности), копирайтер сам решает что использовать. НЕ режет за копирайтера, НЕ грузит техническими деталями. Может ПРЕДЛАГАТЬ (предложения идут обратно стратегу — в Этапе 2 через Директора; в Этапе 1 пишет в заметки, Алик читает).
Оценивает через призму Claude Code + доступных инструментов — НЕ ограничен навыками Алика (с Claude Code возможно многое).
Вход: strategist_brief.md.
ДВА выхода (оба сразу):
  - product_spec_brief.md — для копирайтера. Сжатая рамка реальности: что реально + цифры, что не обещать. Без технических потрохов.
  - product_plan.md — для Алика. Подробный план реализации: что, как, стек, этапы, готовый роадмап который останется запустить в новом проекте для клиента.
Честность: знает → оценка; не уверен → ищет в интернете, проверяет (API, цены, лимиты); не решил → эскалация. Цифры обоснованы или честное "надо измерить/прототип". НЕ сочинять.
Финальная проверка реализуемости — за Аликом.
Tools: Read, Write, Skill, WebSearch, WebFetch (интернет для проверки фактов).
Модель: opus или sonnet (решить на сборке).

### dr-copywriter ✅ собран (НЕ тестирован)
Вход: strategist_brief.md + product_spec_brief.md (рамка реального от архитектора).
Продаёт хотелки клиента в пределах реального, оформляет продающе (копирайтер = и маркетолог). Оркеструет skills: headline-matrix, objection-crusher, conversion-path-builder, copywriting → чистка generic-language-killer → stop-slop (обязательный gate ≥35/50) → humanizer.
Выход: copywriter_draft.md. Доверяет брифу, в транскрипт не лезет.
Tools: Read, Write, Edit, Skill.

### landing-designer 🛠 собран (черновик, не тестирован)
Вход: copywriter_draft.md. Паттерн design-bridge + skill frontend-design (первым). Выход: design_spec.md. Anti-convergence (каждый лендинг уникален). Cialdini-триггеры. Модель opus.

### frontend-dev 🛠 собран (черновик, не тестирован)
Вход: design_spec.md + copywriter_draft.md (точные слова). Узко под статический HTML, деплой Vercel — отдельным человеческим шагом (сам НЕ деплоит). Без мультифреймворк-раздувания. Lighthouse ≥95, accessibility, SEO. Выход: код в deliverables/<slug>/.

### Директор — оркестратор 🛠 собран (черновик, не тестирован), обязателен для боевой работы
Запускает весь pipeline по команде "собери лендинг для <клиент>". Оркеструет 5 агентов (sequential, файловый handoff).
ЭТАП 1: прямой прогон цепочки.
ЭТАП 2: читает _agent_notes.md, обрабатывает "поднятие руки" — маршрутизирует вопросы/предложения между агентами, принимает эскалации (агент→интернет→Директор→Алик).
ДИАГНОСТИЧЕСКИЙ ОТЧЁТ (важно для Алика): после прогона — отчёт о работе офиса: какой агент что сделал, заметки агентов, решения Директора, затыки/переделки, эскалации. Алик скидывает отчёт для анализа → диагностика проседаний офиса.
Human gates: Алик проверяет на ключевых точках (бриф, product_plan, копи, перед деплоем). Директор оркеструет между gate'ами, не заменяет человека.
Модель: opus. Паттерн "When invoked / Integration with other agents".

## Голос сотрудника (_agent_notes.md)
Файл ОБЩИЙ на клиента (clients/<slug>/_agent_notes.md), в папке клиента → пометка клиента не нужна.
Формат: "## КТО → КОМУ · дата" + замечание/предложение + важность.
ЭТАП 1: агенты пишут, Алик читает и дописывает решения вручную ("## Решение (Алик)").
ЭТАП 2: Директор читает, маршрутизирует, ведёт решения сам.
Правило: писать только когда реально есть что сказать (не спамить).
