# CLAUDE.md — Кастдевы для AI-автоматизации

Это рабочая система для проведения и обработки кастдев-интервью с потенциальными клиентами на услугу AI-автоматизации бизнеса.

## Система разработки (Компас)

Этот проект работает по методологии «Компас разработки»:
- **COMPASS.md** — чеклист валидации, перечитывать перед завершением любой задачи
- **failures.md** — журнал уроков (LESSONS), дописывать после каждой коррекции
- **Анти-паттерны** (ниже в этом файле) — чего не делать
- **BACKLOG.md** — отложенные задачи

Перед тем как сказать «готово» — пройди COMPASS.md.

## Контекст

**Кто я:** Алик. Frontend-разработчик в Ozon, параллельно строю услугу по AI-автоматизации (Claude Code, агенты, n8n, Telegram-боты) для малого и среднего бизнеса. Работаю с бизнес-коучем.

**Метод:** провожу кастдевы по структуре, выстроенной с коучем (см. `shared/custdev_protocol.md`). На основе разговора готовлю персональный разбор того, что и как можно автоматизировать у клиента — это второе касание после звонка.

**Цель текущей фазы:** наработать первые 5–10 кейсов для отработки услуги и формирования портфолио. Деньги — второстепенно, главное результат.

## Папка inbox/

**Транзитный буфер** для запуска новых клиентов. Положи сюда аудио + опционально файл наблюдений (`.md`), запусти «новый кастдев» — Claude Code сам найдёт файлы и возьмёт.

**Поведение:**
- Аудио/видео автоматически сканируется в начале опросника kickoff. Один файл — берётся без вопроса (с безопасными проверками: длительность, расширение). Несколько — спросит какой. Нет файлов — спросит путь снаружи.
- Аудио/видео **копируется** в `clients/<slug>/00_raw/` → **сразу удаляется** из inbox (только после успеха копирования).
- Файл наблюдений (`.md`) тоже сканируется автоматически. Содержимое читается, вставляется в `meta.md`, файл удаляется из inbox после успеха записи.
- Если копирование/чтение упало — файл **остаётся в inbox** для повторной попытки (rollback).
- `trim_video` при ручном вызове на файле из inbox ведёт себя так же — копирует в 00_raw, удаляет из inbox.
- **Другие файлы в inbox не трогаются никогда** — Claude Code удаляет только те файлы, которые сам взял для текущего pipeline.
- Оригиналы хранятся у пользователя на устройствах (телефон, диктофон) — это настоящий бэкап.
- В `clients/<slug>/00_raw/` — оригинал для проекта (не удаляется никогда после обрезки).

**Принцип:** inbox = рабочий стол. Что лежит — то ещё не запустили. После запуска уходит в папку клиента.

## Workflow по клиенту

Два пути:

- **Быстрый путь — `kickoff`.** Один опросник из трёх блоков в начале (тех. параметры, качество исходника, субъективные наблюдения), потом конвейер сам гонит шаги 1–9 без пауз до финального PDF. Все ручные данные собираются на старте — после запуска пользователь не нужен до самого конца. Триггер — «новый кастдев», «начнём кастдев».
- **Ручной путь — отдельные триггеры.** Когда что-то нестандартное (часть уже сделана, нужно перепрогнать одну стадию, странный кодек, отладка) — каждый шаг можно вызвать своим триггером (`new_client`, `trim_video`, `enhance_audio`, `transcribe`, `fill_meta`, «разбери», «упакуй»). Скиллы независимые, можно начать с середины.

Шаги (обоих путей одинаковые, отличается только способ запуска):

### Шаг 1. Создать папку
```bash
./scripts/new_client.sh vladimir
```
Скрипт создаёт скелет папки. Имя/деятельность в `meta.md` подставляются автоматически из фразы пользователя через скилл `new_client`.

### Шаг 2. Положить исходник
Видео или аудио (webm с Телемоста, mp4 с Zoom, m4a-бэкап) — в `clients/<имя>/00_raw/`. Скилл `trim_video` извлечёт оттуда нужный кусок и положит готовый `.m4a` в `01_audio/`. Если файл сначала оказался в `~/Загрузки/` — скилл сам переместит его в `00_raw/` после обрезки.

### Шаг 3. Улучшить аудио (если запись грязная)
Скилл `enhance_audio` через ffmpeg-фильтры чистит запись от фонового шума и выравнивает громкость — поднимает точность транскрибации и диаризации на грязных записях. Применяется **перед** отправкой в Deepgram (чистое аудио = меньше ошибок и точнее разделение спикеров). Три режима:
- **Хорошее качество** (Телемост, Zoom, чистая комната) — пропустить, transcribe идёт на оригинале.
- **Среднее** (диктофон/телефон, тихо) — лёгкий: `highpass=80 + loudnorm`.
- **Грязное** (офис, улица, эхо) — агрессивный: `+ lowpass + afftdn + acompressor`.

Выход — `clients/<имя>/01_audio/<slug>_enhanced.m4a` (рядом с оригиналом, не перезаписывает). Если шаг провалился — fallback на оригинал, transcribe возьмёт его. В `kickoff` режим выбирается опросником (Блок B), при ручном вызове — спрашивается явно.

### Шаг 4. Транскрибировать
```bash
python3 -u scripts/transcribe.py clients/vladimir/01_audio/call.m4a \
    -o clients/vladimir/02_transcript/
```
Транскрибация идёт через **Deepgram Nova-3 + диаризация v2** (облако) — разделение спикеров «кто говорит» из коробки, локальный GPU/voice-input не задействуются. Ключ `DEEPGRAM_API_KEY` читается из `custdevs/.env`. Скилл `transcribe` сам выбирает enhanced-версию из `01_audio/`, если она есть; иначе — оригинал. Час аудио обрабатывается за ~0.5–2 минуты. Получаем `.transcript.md` (с таймкодами `**[ЧЧ:ММ:СС–ЧЧ:ММ:СС]**` и метками `[Спикер N]`), `.transcript.txt` (чистый), `.transcript.json` (нормализованные сегменты + сырой ответ Deepgram).

### Шаг 5. Автозаполнить meta.md
Открыть `templates/meta_prompt.md`, подставить туда содержимое текущего `meta.md` и свежей расшифровки, отдать в Claude. Скилл `fill_meta` делает это сам: читает оба файла, подставляет в промпт, сохраняет результат поверх `meta.md` (с бэкапом). На выходе — meta с фактами и дословными цитатами с таймкодами. Раздел `## Контекстные наблюдения автора (kickoff)` (если был добавлен на старте через опросник) `fill_meta` не трогает.

### Шаг 6. Разобрать структуру
Открыть `templates/structure_prompt.md`, скопировать промпт, отдать в Claude вместе с расшифровкой и `meta.md`. Результат сохранить в `clients/<имя>/03_structure.md`.

### Шаг 7. Упаковать пакет
Аналогично — `templates/package_prompt.md`, на вход подать структуру. Результат в `04_package.md` (markdown с 5 секциями). Это исходник для PDF. В `kickoff` запускается автоматически после шага 6.

### Шаг 8. Сгенерировать PDF
Скилл `generate_pdf` парсит `04_package.md` по якорным заголовкам, рендерит через `templates/package_template.html` + WeasyPrint (Python API), проверяет вёрстку. Результат — `clients/<имя>/05_final.pdf`. Это и есть документ для отправки клиенту (вместе с сопроводительным из `clients/_template/SEND_TEMPLATE.md`).

> Примечание: до архитектурной правки 2026-05-03 субъективные наблюдения автора (характер, невербалика, внутренние реакции) дозаполнялись руками после шага 5, и kickoff делал паузу. Сейчас эти данные собираются в Блоке C опросника kickoff на самом старте, и pipeline идёт от начала до конца автономно.

## Auto-trigger скиллы

Claude Code в этом проекте автоматически распознаёт следующие намерения пользователя и запускает соответствующие скиллы. Команды и файлы пользователю **не показывать** — выполнять сразу и отчитываться по результату.

| Триггер пользователя | Скилл | Что делает |
|---|---|---|
| «новый кастдев», «начнём кастдев», «прогони кастдев <имя>» | `.claude/skills/kickoff/SKILL.md` | Опросник из 3 блоков + полный автономный конвейер 1–9 без пауз: клиент → архив → обрезка → enhance → транскрибация → meta → разбор → пакет → PDF |
| «добавь клиента <имя>», «новый кастдев <имя>» | `.claude/skills/new_client/SKILL.md` | Создаёт папку клиента и заполняет meta.md |
| «обрежь видео с X по Y», «подготовь файл с X до Y» | `.claude/skills/trim_video/SKILL.md` | ffmpeg обрезка по таймкодам. Если исходник в `inbox/` — копирует в 00_raw и удаляет из inbox после успеха |
| «улучши аудио для <клиент>», «прогони enhance_audio», «почисти запись» | `.claude/skills/enhance_audio/SKILL.md` | ffmpeg-фильтры (highpass/lowpass/afftdn/loudnorm/acompressor) — чистка для Whisper на грязных записях |
| «транскрибируй <клиент>», «расшифруй <клиент>» | `.claude/skills/transcribe/SKILL.md` | Запуск transcribe.py (Deepgram Nova-3 + диаризация) на свежем файле клиента (приоритет — `_enhanced.m4a`, иначе оригинал) |
| «заполни мету для <клиент>», «собери meta» | `.claude/skills/fill_meta/SKILL.md` | Автозаполнение meta.md из расшифровки через `templates/meta_prompt.md` |
| «упакуй» / «перепакуй» (ручная перегенерация) | inline (по `templates/package_prompt.md`) | Сборка финального пакета `04_package.md` по 5 секциям + закрытие |
| «сделай pdf для <клиент>», «собери pdf», «финальный документ» | `.claude/skills/generate_pdf/SKILL.md` | Рендер `04_package.md` в `05_final.pdf` через WeasyPrint, постпроверка вёрстки |
| «задеплой лендинг», «выложи на vercel», «обнови лендинг» | `.claude/skills/deploy_landing/SKILL.md` | Деплой статического HTML-лендинга на Vercel (`vercel --prod --yes`), возврат URL |
| «сделай лендинг для клиента», «лендинг для <X>», «запусти офис», «директор» | `.claude/skills/director/SKILL.md` | Оркестратор лендинг-пайплайна (РОЛЬ/СКИЛЛ в текущей сессии, не субагент). Пикер клиента → проверка транскрипта → цепочка стратег→архитектор→копи→дизайн→фронт + гейты qa(первый)/sales → превью + диагностический отчёт + запись в `_runs_registry.md`. Один клиент за прогон (изоляция = терминал на клиента). Прод-деплой на паузе (только превью). |

**Правила:**
- Перед выполнением скилла сложнее одной команды — кратко покажи что собираешься делать
- Если контекста для параметров не хватает (имя клиента, таймкоды, путь к файлу) — спроси одним конкретным вопросом, не списком
- Имена клиентов запоминай в текущей сессии: после `new_client` все следующие команды по умолчанию относятся к этому клиенту, пока пользователь не сменит контекст
- `trim_video` после успешной обрезки перемещает исходник из `~/Загрузки/` или другого внешнего места в `00_raw/` текущего клиента, чтобы все материалы по клиенту лежали в одном месте

## Самообучение на ошибках

Файл `failures.md` в корне проекта — append-only лог наблюдений: что сломалось, что прошло криво, что неожиданно выяснилось.

**Перед задачей:** grep `failures.md` по тегам относящимся к задаче. Например, перед обрезкой видео:
```bash
grep -A 5 "#ffmpeg\|#trim" failures.md
```
Если есть релевантные записи — учти их в плане выполнения.

**После задачи — три класса записей.** Писать в `failures.md` (автоматически, без запроса пользователя), если задача попадает в один из них:

- ❌ **Провал** — что-то сломалось и было починено. Теги по сути: `#ffmpeg`, `#deepgram`, `#network` и т. п.
- ⚠️ **Деградация** — задача завершилась, но с заметным отклонением от ожидаемого (медленно, низкое качество, неожиданный fallback). Например: «GPU режим работает, но в 5 раз медленнее ожидаемого». Теги: `#performance`, `#quality`, `#degradation` плюс предметные.
- 💡 **Неочевидное знание** — обнаружилось ограничение или особенность окружения, которое легко забыть. Теги: `#environment`, `#machine` плюс предметные.

**НЕ записывать:**
- Успешные задачи без отклонений
- Мелкие опечатки, разовые случайные сбои
- Известные ограничения, уже описанные в `HOWTO_*.md` или `README.md` (там для них уже есть место)

**Формат записи** — в шапке `failures.md`. Главное — теги, чтобы будущий grep поднял запись на смежной задаче.

**Кто пишет:** Claude Code сам, после каждой задачи где есть один из трёх триггеров. В отчёте пользователю — упомянуть фактом одной строкой: «Записал в failures.md (теги: #X #Y)».

## Бэклог улучшений

Идеи улучшения системы накапливаются в `BACKLOG.md`. Принцип — делать только то, что закрывает уже проявленную боль из реальной работы. Перед добавлением нового скилла или фичи — заглянуть туда: возможно идея уже описана с условием запуска.

## Правила работы Claude в этом проекте

1. **Точные формулировки клиента — святое.** При разборе цитируй человека дословно. Его слова потом возвращаются ему же — это ключевая техника закрытия.
2. **Не выдумывай боли и желания.** Если в расшифровке чего-то нет — пиши «не выявлено», не додумывай.
3. **Ставь под сомнение.** Если человек говорит одно, но видны противоречия — подсвети их в разделе «Противоречия и неясности».
4. **Конкретика инструментов.** В разделе про автоматизацию — конкретные стеки и оценки сложности (1–2 дня / неделя / месяц), не размытые формулировки.
5. **Не продавай в тексте.** Разбор должен быть ценен сам по себе, без призыва купить.

## Анти-паттерны (чего НЕ делать)

Собирается из реальных коррекций. Каждый раз когда Алик перенаправляет — добавляй сюда.

- НЕ строить «палатку из говна и палок» — решение должно быть устойчивым, не «лишь бы работало»
- НЕ уходить в сторону от задачи без спроса
- НЕ делать сверх задачи молча — сначала спросить
- НЕ отмечать готовым то что не запускал и не проверял
- НЕ изобретать своё там где есть существующий паттерн проекта — сначала прочитать соседние файлы
- [дальше дописывается по мере коррекций]

## Известные ограничения

- **Транскрибация облачная (Deepgram).** Нужен интернет и валидный `DEEPGRAM_API_KEY` в `custdevs/.env` (шаблон — `.env.example`). Без ключа `transcribe.py` останавливается с понятной ошибкой. Локальный GPU/VRAM/voice-input для транскрибации больше не задействуются.
- **Прямая отправка файла.** `transcribe.py` шлёт аудио в Deepgram буфером целиком. Для типичных кастдевов (m4a ~128 кбит/с, 1–2 часа ≈ 60–115 МБ) это в пределах лимитов pre-recorded API. Для аномально больших файлов может понадобиться загрузка по URL — пока не требовалось.
- **Стоимость.** Nova-3 multilingual + диаризация ≈ $0.30–0.50 за час аудио (биллится Deepgram по факту, видно в console.deepgram.com).
- **Legacy: локальный faster-whisper выведен из эксплуатации** (переход на Deepgram — см. `failures.md`, 2026-05-28). Старый путь и `HOWTO_LARGE_V3.md` оставлены в git-истории как справка; для текущего pipeline неактуальны.
