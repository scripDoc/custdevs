# Backlog — идеи улучшения системы

Идеи которые отложены до момента когда станет ясно — реально нужны или нет. Приоритизация по принципу: делать только то, что закрывает уже проявленную боль из реальной работы.

## Формат записи

```
### YYYY-MM-DD — Название
**Что:** 1–2 предложения о сути
**Зачем:** какую боль решает
**Триггер для запуска:** при каких условиях стоит браться (например: «после 3 завершённых кейсов», «если потребуется параллелить работу»)
**Сложность:** S / M / L (часы / день / несколько дней)
```

### 2026-05-02 — Оптимизация VAD на больших аудио в GPU-режиме
**Что:** На 74-минутном тестовом файле VAD-фильтр faster-whisper прогоняется ~10 минут на CPU перед GPU-инференсом. Это съедает большую часть выигрыша от GPU.
**Зачем:** GPU-режим должен давать x5–10 ускорение, но из-за CPU-VAD реальный выигрыш сильно меньше. На длинных кастдевах (час+) разница критична.
**Варианты решения:**
- Вынести VAD на GPU (faster-whisper поддерживает vad_filter с GPU)
- Отключить VAD в GPU-режиме (он нужнее для CPU чтобы не молотить тишину; на GPU инференс быстрый, можно и без него)
- Использовать более лёгкий VAD (silero вместо webrtcvad)
**Триггер для запуска:** после 3–5 кастдевов с длинными записями, когда станет ясно сколько реально съедает VAD на боевых задачах
**Сложность:** S (правка `scripts/transcribe.py`, без архитектурных изменений)

### 2026-05-03 — Стратегия реализации: кастом vs готовые блоки vs команда

- Кастомный сервис = 80-300 часов разработки

1. Библиотека готовых блоков (CRM-интеграция, Telegram-бот квалификатор, ElevenLabs-голосовые, Whisper-транскрибация) — собирается под клиента из готовых компонентов. Требует инвестиции в построение библиотеки.

3. Команда исполнителей — Алик архитектор, кто-то другой реализует. Нужно искать исполнителей.
4. Гибрид — сочетание всех трёх.

### 2026-06-02 — Сквозная память (ров `nikita_muzh_klub`) — НЕ построена, только роадмап
**Что:** «Сквозная память по всем проектам между сессиями» заявлена в `product_plan.md` как **главный ров** и как часть **MVP**. По факту **не построена** — это пока только роадмап/вижн.
**Текущее состояние бота:** работает на контекстном окне / последних ~10 сообщениях, **сессия сбрасывается**. Между сессиями и между доменами (проектами) контекст НЕ сшивается. То есть сейчас это ровно та session-scoped память, что у коробок, — рва нет в железе.
**Дисциплина (важно, до постройки):** **не подавать сквозную память как готовое** — ни в копи, ни на созвоне. На созвоне — только как **вижн/траекторию** («куда идём», не «что уже есть»). Иначе это мина уровня «Джарвис читает чаты» у коуча: сильнейший буллет, который детонирует первым на «а как именно сейчас?».
**Что построить:** отдельный слой памяти — **хранилище + извлечение**, которое (а) переживает сессии, (б) сшивает домены (проекты). Не контекстное окно, а персистентный слой (SQLite/Postgres + извлечение по проекту, вектор позже — как в плане).
**Где обкатывается:** прототип слоя идёт в **Рей Вектор** → паттерн переносится в клиентский продукт (`nikita_muzh_klub` и далее).
**Зачем:** ров — единственное, что отличает продукт от коммодити-ботов. Пока он не в железе, в продажах его держать как направление, а не как факт (честность = ядро офиса).
**Триггер для запуска:** прототип памяти в Рей Векторе доведён до рабочего паттерна → перенос в продукт `nikita_muzh_klub` при старте реализации.
**Сложность:** M–L (персистентный слой + извлечение, кросс-доменное сшивание).
